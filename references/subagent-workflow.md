# Subagent 编排协议

本协议用于 `campus-repo-knowledge` 的大型仓库初始化，以及范围未知的代码改动同步。目标是让主 Agent 用一次廉价盘点划定边界，再让 subagent 在有限范围内并行取证，最后由主 Agent 统一判断和写入知识库。

## 何时必须拆分

满足任一条件就必须使用 subagent（环境不支持时按同样分片串行执行）：

- 仓库包含多个构建单元、服务、应用、包或语言生态。
- 候选源码文件超过约 300 个，或仅目录与入口信息不足以在主 Agent 的合理上下文内判断主要模块。
- 初始化需要调查 4 个及以上相对独立的模块或横切主题。
- 未知改动跨越 3 个及以上顶层模块、50 个以上文件、多个提交，或同时涉及 API、数据模型、配置、迁移、测试等不同变更面。
- 单片预计需要读取超过上下文预算的 20%，或整体调查预计超过预算的 50%。

只有单构建单元、边界清楚且源码较少的小仓库，或变更集中在少量强相关文件时，才可不拆分。主 Agent 应记录未拆分理由。

## 先盘点，后分片

主 Agent 先做一次只看元数据和结构的廉价盘点，不逐文件阅读实现：

1. 确认仓库根、工作区状态、比较基线与已有 `.repo-knowledge/`。
2. 列出两到三层目录、构建清单、包管理文件、语言入口、测试目录和部署/CI 配置；排除依赖、构建产物、缓存、生成代码和大型二进制目录。
3. 初始化时，从构建单元、稳定目录边界和公开入口形成模块候选；把认证、持久化、协议、配置、测试等跨模块主题单独标记。
4. 同步时，先取变更文件名、状态、提交摘要和必要的 diff 统计，再按“同一业务能力、同一构建单元、直接依赖关系、同一提交意图”聚成变更簇。
5. 为每片写明允许读取的路径、必要邻接依赖、禁止范围和预期产出；重叠路径必须显式说明原因。

分片优先级为：稳定构建模块或服务 > 业务能力目录 > 变更簇 > 横切主题。不要按机械等量文件数切片，也不要把一个紧密调用链拆到多个互不知情的任务中。

## 职责边界

**主 Agent**负责盘点、选择基线、设计分片、控制并发与预算、提供共享事实、处理跨片冲突、抽查源码、决定知识应落入的位置、写入正式文档、刷新索引并完成验收。主 Agent 对全局架构结论和最终文本负责。

**Subagent**只在授权范围内调查源码、测试和必要依赖，提炼可复核事实，标注推断与未知项，并按统一格式返回。Subagent 不直接定义全局模块边界，不擅自修改知识库，不把局部观察推广为仓库级结论。

## 每个任务的最小输入

派单至少包含：

- 场景：初始化或未知改动同步。
- 仓库根，以及本片名称和目标。
- 允许读取的路径/文件；最多附带少量必要邻接路径。
- 初始化的模块候选与入口，或同步的基线、目标 ref、变更文件清单/对应 diff 范围。
- 已知共享事实，如语言、构建方式、生成目录、既有知识库相关链接。
- 要回答的问题、证据要求、返回格式、时间或上下文上限。
- 明确禁令：不得全仓扫描、不得扩展到未授权模块、不得修改文件；确需越界时只报告所需路径与理由。

禁止把完整仓库树、所有 diff、其他模块全文复制给每个 subagent。共享信息只发送完成该片所需的最小集合。

## 统一返回格式

每个 subagent 必须返回以下中文 Markdown；没有内容的栏目写“无”，不得省略：

```markdown
## 分片结果：<名称>
- 状态：完成 | 部分完成 | 失败
- 调查范围：<实际读取的相对路径或 diff 范围>
- 一句话结论：<本片最重要的结论>
- 置信度：高 | 中 | 低

### 事实与证据
- <事实>；证据：`相对路径`（符号/行号/提交，可用时提供）

### 模块或行为说明
- 职责/入口/数据流/公开契约/测试方式：<仅写已核对内容>

### 同步影响
- <行为变化、兼容性、配置/迁移/测试影响；初始化任务写“无”>

### 推断
- <明确写“根据代码/提交推断”，并说明依据>

### 风险与待确认
- <冲突、缺口、未读依赖、需要主 Agent 决策的事项>

### 建议归档位置
- `<知识库相对路径>`：<建议新增或更新的要点>
```

证据必须指向仓库相对路径；结论与证据分开写。无法确认的意图不得伪装成用户事实。

## 并发与上下文预算

- 默认并发 3 到 5 个；小仓库 2 到 3 个，超大仓库最多 6 到 8 个。并发上限还应受工具限制、磁盘压力和任务依赖约束。
- 每片以可在总上下文 10% 到 20% 内完成为宜，通常覆盖一个模块或一个紧密变更簇；预计超过 20% 时继续拆分。
- 预留至少 30% 总上下文给主 Agent 合并、冲突核查、写文档和验收；派单与共享背景尽量控制在 10% 以内。
- 先并发独立叶子模块，再处理依赖其结论的横切主题。不要为了凑并发拆散强依赖链。
- 返回要求摘要化：保留事实、证据和风险，不回传大段源码、完整 diff 或冗长目录列表。

## 冲突处理

主 Agent 按“源码与测试现状 > 构建/配置事实 > 已验证知识库记录 > 提交信息 > subagent 推断”的顺序裁决。两个结果冲突时：

1. 先检查比较基线、读取范围和术语是否不同。
2. 让冲突双方各提供最小证据，或由主 Agent 直接读取争议文件与调用点。
3. 能按作用域并存的结论分别归档，不能并存的结论以复核结果为准。
4. 仍无法确认时，不强行统一；在 inbox 或正式文档中标为待确认，写清两种解释及证据。

主 Agent 应统一模块命名、术语和链接，合并重复发现，但不得在去重时丢失相反证据。

## 失败与超时降级

- 单片超时或返回过大：保留已取得的结构化结果，将范围减半后重派；不要让其他 subagent 接手整仓。
- 工具或解析失败：退回到路径、构建声明、公开接口和测试的保守调查，并把缺失能力写入风险。
- Subagent 越界或缺少证据：拒收越界部分，只要求补充指定路径的最小证据。
- 多次失败：主 Agent读取该片最关键的入口、契约和测试，形成“部分完成”结论，其余进入待确认项。
- 无 subagent 能力：主 Agent按既定分片串行处理，每片完成后先写临时汇总，再释放实现细节继续下一片。

任何降级都不能把推断升级为事实，也不能因为一片失败阻塞其他独立分片的合并。

## 初始化派单模板

```text
你正在为 campus-repo-knowledge 执行大型仓库初始化调查。
仓库根：<repo>
分片：<模块/横切主题名称>
目标：核对本片的职责、入口、公开契约、关键数据流、扩展点、测试方式和维护风险。
允许读取：<路径列表>
必要邻接范围：<少量路径或“无”>
已知事实：<语言、构建单元、入口、生成目录等>
重点问题：<问题列表>

只调查授权范围；禁止全仓扫描、修改文件或自行定义全局架构。确需越界时不要读取，只在“风险与待确认”中列出路径和理由。事实必须附仓库相对路径证据，推断必须明确标注。请严格按《Subagent 编排协议》的统一返回格式输出，并把结果控制在 <字数/上下文上限> 内。
```

## 同步派单模板

```text
你正在为 campus-repo-knowledge 执行未知改动同步调查。
仓库根：<repo>
比较范围：<base-ref>..<target-ref 或工作区>
变更簇：<名称与简述>
允许读取的变更：<文件/diff 列表>
必要依赖与测试：<路径列表>
相关既有知识：<知识库路径与一句话摘要>
重点问题：行为发生了什么变化；影响哪些契约、配置、迁移和测试；哪些需求意图只能推断；应更新哪些知识文档。

只检查本变更簇及列出的必要依赖；禁止全仓扫描、修改文件或顺手调查其他变更簇。发现跨簇影响时只报告路径、影响和建议复核对象。事实必须附仓库相对路径或提交证据，意图推断必须写“根据代码/提交推断”。请严格按《Subagent 编排协议》的统一返回格式输出，并把结果控制在 <字数/上下文上限> 内。
```

## 最终验收清单

- [ ] 已记录场景、仓库根、初始化范围或同步基线；不确定假设已显式标注。
- [ ] 已完成一次廉价盘点，并排除依赖、产物、缓存、生成代码和二进制噪声。
- [ ] 达到强制条件时已分片；每片边界清楚，且没有 subagent 重复全仓扫描。
- [ ] 每份返回都符合统一格式，关键事实有相对路径证据，推断与事实分离。
- [ ] 主 Agent 已处理重复、冲突、跨模块影响和失败分片，并抽查高风险结论。
- [ ] 初始化已覆盖项目入口、关键模块、主要运行链路、测试方式和高风险约束。
- [ ] 同步已覆盖行为、契约、配置/迁移、测试影响，并记录 inbox 处理去向。
- [ ] 持久结论已写入正确的项目、模块、需求或决策文档，术语和链接一致。
- [ ] 已刷新机械清单与 `INDEX.md`，检查坏链、重复结论和遗留 `待补充`。
- [ ] 工作区仅包含预期知识库改动，未覆盖他人的未提交修改。
