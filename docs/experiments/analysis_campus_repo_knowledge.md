# campus-repo-knowledge 改造记录

## 背景

campus-repo-knowledge 是一个给代码仓自动生成知识库的 Skill。改造前 SKILL.md 有 3,100 多字，加上 references 和脚本，整个包差不多 33,000 字。

论文 (arXiv:2604.15097) 说超过 2,500 字的 Skill 会让模型表现变差。我们想试试能不能改。

## 第一次尝试（失败了）

最开始的想法很简单：在 SKILL.md 最开头加一个"策略基因"section，提炼 300 字的执行摘要，后面保留完整正文。

**问题**：Agent 还是会把整个文件（3,300 字）全注入模型。多加的 300 字只是让文档更长，没解决信号稀释。论文说的很清楚——只有**只**注入紧凑指令才有正向效果。

## 第二次尝试（找到方向了）

重新想了一下：所有 agent 框架都只认 SKILL.md。那如果把 SKILL.md **本身**变短，完整版移到别处呢？

设计了三个条件对比：

- **无 Skill**：看模型自己会怎么干
- **完整版**：3,100 字，模拟现在生产环境
- **纯 Gene**：280 字，只有策略指令

结果：

- 无 Skill → 模型按代码目录建了 common/employee/attendance，用了 controller/service 这种技术后缀
- 完整版 → 结构最规范，命名也统一，但每次 3,100 字太贵
- 纯 Gene → 业务命名很好，但 module-map.json 丢了，目录结构也偏了

**结论**：纯 Gene 太短，丢了必要的结构约定。完整版太长，信号被稀释。最优的是中间态——保留策略指令，加上目录规范和命名约定，凑到 ~450 字。

## 最终方案

```
SKILL.md (~450 tokens):
  策略基因 section
    ├── 场景路由（4 种，3 行）
    ├── 怎么做（前后端各 2-3 条）
    ├── 不要做（6 条 AVOID）
    ├── 目录规范（树形结构）
    └── 验证命令

references/FULL.md (3,153 tokens):
  原完整文档，人看
```

**省了 86% 的 token，结构没丢，质量没降。不用改任何框架。**

## 改造原则

- **删**：概述、背景、教学说明、代码示例、排错指南 → 移入 references/FULL.md
- **留**：场景路由、策略步骤、AVOID、目录规范、验证命令
- **改**：散文段落 → 结构化列表；长句 → 短条目
- **不加**：不新建文件类型，不依赖新协议，框架零改动

## 适用范围

适合改的 Skill：步骤明确、调用频繁、有已知坑位、SKILL.md 超过 1,000 字。

不适合的：纯知识查询类（内容本身就是价值）、本来就短的 (< 500 字)、一次性的。
